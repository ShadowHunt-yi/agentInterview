# Agent 工程

## Q9. LangChain 和 LangGraph 有什么区别

LangChain 更像 LLM 应用组件库，提供 prompt、model、retriever、tool、chain 等封装。LangGraph 更强调有状态、多步骤、可分支的 Agent 编排。

| 对比 | LangChain | LangGraph |
| --- | --- | --- |
| 核心 | 组件和链式调用 | 状态图和流程编排 |
| 适合 | 简单 RAG、工具封装、快速原型 | 多轮状态、条件分支、人工确认、复杂 Agent |
| 流程 | 更偏线性 chain | 显式节点和边 |
| 状态 | 通常自己管理 | StateGraph 统一管理 |

一句话：

> LangChain 适合搭积木，LangGraph 适合画流程图并让它可执行。

## Q33. Agent 面试常见问题：模型选型

模型选型不要只说“越大越好”，要按任务拆：

| 场景 | 选择重点 |
| --- | --- |
| 意图分类、路由 | 小模型，低延迟、低成本 |
| RAG 问答 | 中等模型，关注忠实度和长上下文 |
| 工具调用 | 函数调用稳定性、JSON 约束能力 |
| 复杂规划 | 强推理模型，更大参数或 reasoning 模型 |
| 高并发客服 | 成本、吞吐、缓存、降级策略 |

选型维度：

- 准确率：领域 case eval。
- 延迟：P50/P95/P99。
- 成本：输入输出 token、缓存命中。
- 上下文：文档长度和历史轮次。
- 稳定性：格式遵循、工具调用、拒答策略。
- 部署：云 API、自部署、数据合规。

面试话术：

> 我会先分层选模型：路由用小模型，复杂回答用主模型，强推理或高风险场景再升级模型。最后用 eval harness 跑固定 case，而不是只凭主观体验选。

## Q34. Harness 有了解吗

Harness 在这里可以理解为模型或 RAG 系统的自动化评测框架。它把测试集、运行器、指标和报告串起来，保证每次改 prompt、检索参数、模型版本后都能回归。

一个 RAG harness 通常包括：

- 测试集：query、期望答案、必须命中文档、禁止内容。
- 运行器：批量调用 RAG 链路。
- 指标：hit rate、MRR、faithfulness、answer relevance、latency。
- 对比：新旧版本差异、失败 case 列表。
- 门禁：低于阈值不允许上线。

面试里可以补：

> Harness 的价值是把“感觉变好了”变成“指标确实变好了”，尤其适合 RAG 参数调整和模型升级。

## Q35. 文档有很多类型，解析怎么做，怎么保证质量

文档解析要按类型分层：

| 类型 | 解析策略 |
| --- | --- |
| PDF | 文本层优先，扫描件走 OCR，保留页码 |
| Word | 提取标题层级、段落、表格、图片说明 |
| Excel | 按 sheet、表头、区域块解析 |
| HTML / Markdown | 保留标题、列表、代码块和链接 |
| 图片 | OCR + 图像说明，必要时人工校验 |

质量保障：

1. **结构保真**：保留标题路径、页码、表格表头、来源 URL。
2. **解析校验**：空文本率、乱码率、重复率、表格列数异常。
3. **抽样人工验收**：高价值文档人工 spot check。
4. **切分前清洗**：去页眉页脚、目录噪声、版权重复块。
5. **可追溯引用**：每个 chunk 带 doc id、page、section path。
6. **解析失败降级**：失败文档进入待处理队列，不直接入库污染检索。

面试话术：

> 我不会把所有文档都当纯文本切。解析阶段要先保结构，再做清洗和切分；质量上用自动规则检查乱码、空文本、重复块和表格异常，关键文档再抽样人工验收。

## Agent 工程深挖追问排查

### LangGraph 追问怎么答

面试官常追问的不只是“区别”，而是你为什么需要图。

| 追问 | 回答要点 |
| --- | --- |
| 为什么不用普通 if/else？ | if/else 可以做，但复杂后难测试、难观测、难插入 HITL；图结构更可维护 |
| State 里放什么？ | intent、retrieval_results、tool_calls、pending_confirmation、eval_score、final_answer 等 |
| 节点怎么设计？ | 每个节点只做一件事，输入 state，返回局部更新 dict |
| 条件边怎么设计？ | 路由函数只读 state，返回下一个节点 key，避免副作用 |
| 怎么恢复中断？ | checkpoint / 持久化 pending operation，人工确认后继续执行 |

一句话：

> Agent 工程的难点不是让 LLM 多说几句话，而是把状态、分支、工具、副作用和人工确认管理清楚。

### 工具调用为什么要 HITL

工具分两类：

| 工具类型 | 示例 | 策略 |
| --- | --- | --- |
| 查询类 | 查订单、查库存、查政策 | 可直接执行 |
| 写入类 | 取消订单、退款、修改信息 | 必须确认 |

原因：

- LLM 可能误判用户意图。
- 写操作有业务后果。
- 客服系统需要审计和责任归属。

面试回答：

> 我会让工具自己声明 `requires_confirmation`，编排层根据这个字段决定直接执行还是生成确认卡片。这样新增工具时不会把确认逻辑散落在 prompt 里。

### 模型选型怎么做成体系

不要只说“用 GPT-4”或“用 Qwen”。要按链路拆模型：

| 子任务 | 模型策略 |
| --- | --- |
| 意图分类 | 小模型或规则优先，低延迟 |
| Query rewrite | 小模型，要求稳定 JSON |
| RAG 回答 | 主力模型，关注忠实度 |
| 工具调用 | 函数调用能力强、格式稳定 |
| 高风险决策 | 更强模型或人工确认 |
| 质量评估 | 规则 + LLM judge 混合 |

选型最终靠 eval：

- 准确率。
- 格式遵循率。
- 工具调用成功率。
- 幻觉率。
- P95 延迟。
- 单次会话成本。

### Harness 怎么避免“自嗨评测”

评测集要覆盖真实失败模式：

- 精确编号查询。
- 模糊问法。
- 多跳问题。
- 知识库不存在的问题。
- 工具参数不全。
- 应拒答或转人工的场景。

指标要分层：

| 层级 | 指标 |
| --- | --- |
| 检索 | hit rate、MRR、NDCG |
| 重排 | top1 accuracy、rerank score 分布 |
| 生成 | faithfulness、answer relevance、must include |
| 工具 | tool selection accuracy、argument accuracy |
| 服务 | latency、cost、fallback rate |

### 文档解析追问清单

| 追问 | 回答要点 |
| --- | --- |
| PDF 表格怎么处理？ | 不直接按行拼文本，保留表头、页码、列结构，必要时表格转 markdown |
| 扫描件怎么办？ | OCR 后做置信度检查，低置信度进入人工队列 |
| 怎么防乱码入库？ | 检查乱码率、异常字符比例、空文本率 |
| 图片信息怎么办？ | OCR + caption，重要图人工补说明 |
| 文档更新怎么处理？ | 版本号、doc hash、chunk hash，变更后增量重建 |
| 如何保证引用可追溯？ | chunk metadata 带 document_id、page、section path、source url |
