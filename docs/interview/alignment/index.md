# 训练与对齐

## Q10. 模型训练完之后要干啥

预训练完成后，模型只是学会了语言分布，不一定会按人的指令做事。通常后续流程是：

1. **SFT 指令微调**：用高质量指令数据教模型遵循任务格式。
2. **偏好对齐**：用 RLHF、DPO 等方法让模型更符合人类偏好。
3. **安全对齐**：拒答策略、敏感内容、工具调用约束。
4. **评测与回归**：通用能力、领域能力、幻觉率、工具调用成功率。
5. **部署优化**：量化、推理服务、监控、灰度发布。

面试里可以说：

> 预训练不是终点。面向业务使用时，还要做指令微调、偏好对齐、评测、压缩部署和线上监控。

## Q21. 强化学习是什么机制

强化学习是智能体和环境交互，通过奖励信号学习策略的机制。基本要素：

| 元素 | 含义 |
| --- | --- |
| Agent | 做决策的主体 |
| State | 当前状态 |
| Action | 可执行动作 |
| Reward | 动作后的奖励 |
| Policy | 从状态到动作的策略 |

在 LLM 对齐中，RLHF 通常是：

1. 收集人类偏好数据。
2. 训练奖励模型。
3. 用 PPO 等算法优化语言模型，让输出获得更高奖励。

## Q22. 强化学习和指令微调有什么不同

| 对比 | SFT 指令微调 | 强化学习 / RLHF |
| --- | --- | --- |
| 数据 | 指令-答案样本 | 偏好、奖励或环境反馈 |
| 目标 | 模仿标准答案 | 最大化奖励 |
| 训练信号 | 交叉熵 loss | reward / advantage |
| 优点 | 稳定、简单、可控 | 能优化难以写成标准答案的偏好 |
| 风险 | 受限于示例质量 | 训练不稳定，奖励模型可能被钻空子 |

一句话：

> SFT 是“照着好答案学”，RLHF 是“根据偏好反馈调整输出策略”。

## 训练与对齐深挖追问排查

### 训练完为什么不能直接上线

预训练模型学的是“下一个 token 的统计规律”，不是业务可用性。上线前至少要检查：

| 环节 | 目的 |
| --- | --- |
| SFT | 让模型学会按指令、格式和领域风格回答 |
| 偏好对齐 | 让回答更符合人类偏好和安全要求 |
| 领域评测 | 看业务问题是否真的会答 |
| 安全评测 | 看敏感、越权、注入攻击能否兜住 |
| 推理压缩 | 量化、蒸馏、服务化，降低成本 |
| 线上监控 | 追踪幻觉、负反馈、延迟和成本 |

面试回答：

> 训练完成只是模型能力形成，后训练、评测和部署监控才决定它能不能在业务里稳定使用。

### SFT 数据为什么比参数更重要

SFT 本质是行为模仿。数据质量差会直接教坏模型：

- 答案啰嗦，模型也会啰嗦。
- 格式不稳定，模型工具调用也不稳定。
- 数据里有幻觉，模型会学会编。
- 领域术语不统一，模型输出会不一致。

高质量 SFT 数据要满足：

- 指令清晰。
- 答案有依据。
- 格式一致。
- 覆盖真实场景。
- 包含拒答、澄清、转人工等边界样本。

### RLHF / PPO 怎么讲

RLHF 常见流程：

```text
SFT model
→ 收集多个候选回答
→ 人类标注偏好
→ 训练 reward model
→ 用 PPO 优化 policy
```

PPO 优化时通常还会加 KL 约束，避免模型为了拿高 reward 偏离原模型太远。

面试追问：

> RLHF 的风险是 reward hacking。模型可能学会讨好奖励模型，而不是真的变好，所以需要 KL 约束、人工评估和多维度 eval。

### DPO 和 RLHF 有什么区别

DPO 可以看作更直接地用偏好数据优化模型，不单独训练 reward model，也不跑复杂的 PPO 采样循环。

| 对比 | RLHF / PPO | DPO |
| --- | --- | --- |
| 是否训练 reward model | 通常需要 | 不需要显式 reward model |
| 训练复杂度 | 高 | 较低 |
| 稳定性 | 更难调 | 相对简单 |
| 数据 | 偏好 pair | 偏好 pair |
| 工程成本 | 高 | 低 |

一句话：

> RLHF 是“先学奖励，再用强化学习优化”；DPO 是“直接从偏好对里优化模型更偏向 chosen 而不是 rejected”。

### 强化学习和 SFT 的关键差别

SFT 的 loss 来自标准答案 token：

```text
让模型更像 reference answer
```

RL 的目标来自奖励：

```text
让模型输出获得更高 reward
```

所以：

- SFT 更稳定，适合教格式、教领域话术。
- RL/DPO 更适合优化“有多个可接受答案，但有偏好差异”的问题。
- 对客服/RAG 项目来说，SFT 可以教回答格式，偏好对齐可以教简洁、谨慎、拒绝无依据回答。

### 对齐追问清单

| 追问 | 回答要点 |
| --- | --- |
| SFT 会不会造成灾难性遗忘？ | 会，领域数据过窄或学习率过大时明显；可用混合数据和较小学习率缓解 |
| RLHF 为什么不直接替代 SFT？ | RLHF 需要较好的初始 policy，通常先 SFT 再偏好优化 |
| Reward model 准不准怎么办？ | 多维评测、人工抽检、KL 约束，避免 reward hacking |
| 什么时候不需要 RLHF？ | 小规模业务适配可先 SFT + 规则评测，RLHF 工程成本高 |
| DPO 为什么流行？ | 少了 reward model 和 PPO，训练链路更简单稳定 |
